## Project vault

Durable project knowledge lives in `vault/` — read it before non-trivial work, and keep it current.

- `vault/ARCHITECTURE.md` — components, flow, boundaries, decisions. Read before touching structure.
- `vault/specs/` — one file per feature. Read the relevant spec before implementing it; add or
  update a spec when scope changes.
- `vault/QUALITY.md` — gate commands and the definition of done. Run these before reporting work complete.

When you learn something durable about this project, write it into the vault rather than here.
